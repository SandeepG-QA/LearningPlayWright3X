# Hoisting and TDZ

## 1. Hoisting
Hoisting is the behavior in JavaScript where declarations are moved to the top of their scope during the compilation phase.

### Example with var
```javascript
console.log(a); // undefined
var a = 10;
```

### Explanation
- `var` is hoisted and initialized with `undefined`.
- So accessing it before declaration gives `undefined`.

---

## 2. TDZ (Temporal Dead Zone)
TDZ means that a variable declared with `let` or `const` cannot be accessed before its declaration is executed.

### Example with let
```javascript
console.log(a); // ReferenceError
let a = 10;
```

### Explanation
- `let` and `const` are hoisted but not initialized.
- They stay in the TDZ until the line where they are declared is executed.

---

## 3. Difference Between var, let, and const

| Keyword | Hoisted? | Initial value before declaration | Can be reassigned? |
|--------|----------|----------------------------------|--------------------|
| var | Yes | undefined | Yes |
| let | Yes | TDZ | Yes |
| const | Yes | TDZ | No |

---

## 4. Important Point
```javascript
let a = 5;
if (true) {
    console.log(a); // error if inner let shadows it
    let a = 10;
}
```

This creates a block-scoped `a` inside the block, and the outer `a` is not accessible in that scope before initialization.

---

## 5. Summary
- `var` is hoisted and initialized as `undefined`.
- `let` and `const` are hoisted but remain in TDZ until initialization.
- This is why `let` and `const` are safer than `var`.
